# SupportIQ — Data Model

## 1. Overview

SupportIQ manages customer support tickets. The initial version contains one entity: `Ticket`.

## 2. Ticket Fields

| Field          | Type      | Required | Rule                                                   |
| -------------- | --------- | -------- | ------------------------------------------------------ |
| id             | String    | Yes      | Unique, generated identifier                           |
| title          | String    | Yes      | Must not be blank                                      |
| description    | String    | Yes      | Must not be blank                                      |
| customer_email | String    | Yes      | Basic email validation                                 |
| status         | String    | Yes      | `open`, `in_progress`, or `closed`; defaults to `open` |
| priority       | String    | Yes      | `low`, `medium`, or `high`; defaults to `medium`       |
| created_at     | Timestamp | Yes      | Generated at creation                                  |

## 3. Business Rules

* Ticket IDs are generated by the repository.
* IDs and creation timestamps must not be changed through normal update operations.
* Required text fields must not contain only whitespace.
* Status and priority must use supported values.
* Updates are atomic: if any supplied field is invalid, reject the entire update without changing the ticket.

## 4. Scope

The initial version has no separate Customer entity or AI-based priority classification. Both may be considered in later increments.
